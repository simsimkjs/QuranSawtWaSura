# نسخة الويب — القرآن الكريم (صوت وسورة)

نسخة ويب خفيفة من تطبيق سطح المكتب، تعمل بالكامل داخل المتصفح بدون خادم تطبيقات ولا قاعدة بيانات.
تقرأ نفس ملفات مجلد `quran-data` المستخدم في نسخة JavaFX، وتحفظ الإعدادات والعلامات والتقدّم محليًا
على جهاز المستخدم (`localStorage`).

## التشغيل السريع

> **مهم 1:** لا تفتح `web/index.html` بالنقر المزدوج (بروتوكول `file://`)، لأن المتصفح يمنع
> تحميل ملفات JSON عبر `fetch` في هذه الحالة.
>
> **مهم 2:** استخدم خادمًا يدعم **HTTP Range**، لأن ملفات التلاوة كبيرة ويحتاج المتصفح
> للقفز داخلها عند الانتقال لآية أو تحريك شريط التقدّم. خادم `python -m http.server`
> **لا يدعم Range**، لذا سيفشل القفز داخل الصوت (يبقى التشغيل من البداية فقط).

### Python (موصى به)

```powershell
.\web\serve.ps1
```

أو مباشرة:

```powershell
python web\serve.py -p 8000
```

ثم افتح: <http://localhost:8000/web/>

### Node.js (بديل)

```powershell
npx --yes serve -l 8000 .
```

ثم افتح: <http://localhost:8000/web/>

## البيانات المطلوبة

يجب أن يكون الهيكل بجانب مجلد `web`:

```
quran-data/
  surahs.json            فهرس السور (114 سورة)
  manifest.json          (مُولَّد) توفّر النص/الصوت/التفسير لكل سورة
  search-index.json      (مُولَّد) فهرس البحث المسبق
  quran/001.json ...     آيات كل سورة مع start_ms + qcf/qcf_page
  audio/001.mp3 ...      التلاوات الصوتية
  tafsir/001.json ...    التفسير (اختياري)
```

- السور التي لا يوجد لها ملف في `quran-data/quran` تظهر برسالة واضحة بدل الآيات، ولا يطلبها
  التطبيق أصلًا إذا كان `manifest.json` محدَّثًا (لا ضجيج 404).
- شارة صغيرة بجانب كل سورة تبين: نص وصوت (أخضر)، نص فقط (برتقالي)، أو غير متوفرة (رمادي).
  ويمكن تفعيل «المتوفرة» لإخفاء السور التي لا نص لها.
- إن غاب ملف الصوت، تبقى القراءة والتنقل والبحث متاحة، ويظهر تنبيه عند محاولة التشغيل.
- ملفات الصوت غير مضمّنة في Git (ما عدا عيّنة صغيرة) بسبب حجمها؛ عند النشر على الإنترنت
  يجب رفعها إلى استضافة ملفات أو تخزين سحابي وتعديل مسارها.

### توليد فهارس البيانات

بعد إضافة/حذف/تعديل أي سورة أو ملف صوت أو تفسير:

```powershell
python tools\build_quran_data.py
```

يقرأ المولّد `quran-data/surahs.json` وملفات السور والصوت والتفسير، ويكتب:

- `quran-data/manifest.json` — توفّر النص/الصوت/التفسير وبصمة البيانات (fingerprint).
- `quran-data/search-index.json` — فهرس بحث مسبق (سورة، آية، نص) بدل تحميل 114 ملفًا عند البحث.

للتحقق فقط من أن الملفين محدَّثان (مناسب لـ CI، ولا يحتاج ملفات الصوت):

```powershell
python tools\build_quran_data.py --check
```

> إذا أضفت سورة ولم تعد تشغيل المولّد، ستظل شارة «غير متوفرة» كما هي. وإذا تغيّر النص
> وبقي فهرس البحث قديمًا، يكتشف المتصفح عدم تطابق البصمة ويعيد بناء الفهرس من ملفات السور
> (أبطأ، لكنه يعمل).
>
> حقول الصوت في `manifest.json` تعكس الملفات الموجودة عند تشغيل المولّد. وهي مستبعدة من
> بصمة البيانات ومن فحص `--check` لأن الصوت يُوزَّع خارج Git؛ أعد تشغيل المولّد على خادم
> النشر بعد رفع ملفات الصوت إذا أردت شارات الصوت الدقيقة.

### نصوص وخطوط QCF (مطابقة quran.com)

لعرض الآيات بالخط الافتراضي نفسه الذي يستخدمه [quran.com](https://quran.com) (خط مستقل
لكل صفحة مصحف مع نصوص `code_v2`)، شغّل:

```powershell
python tools\build_qcf_data.py
```

يقرأ السور المتوفرة، ويضيف لكل آية حقلين اختياريين: `qcf` (نص العرض المرمّز) و
`qcf_page` (رقم صفحة المصحف 1–604)، ثم ينزّل خطوط الصفحات المطلوبة إلى
`web/assets/fonts/qcf/pNNN.woff2` ويكتب `web/css/qcf-fonts.css`. في النهاية يحدّث
`manifest.json` و`search-index.json` تلقائيًا (لأن بصمة النص تعتمد على محتوى ملفات السور)؛
استخدم `--no-index` إذا أردت تخطي ذلك.

- `--force` يعيد تنزيل كل الخطوط ويكتب ملفات السور من جديد.
- `--check` يتحقق دون اتصال من وجود الحقول والخطوط وتطابق `qcf-fonts.css` (يُستدعى في CI).
- `--verbose` يطبع كل خط يُنزَّل.

الخط الأساسي `UthmanicHafs1Ver18.woff2` يبقى مستخدمًا للنص العادي ونتائج البحث والتفسير
وقبل اكتمال تحميل خط QCF. يقوم `web/js/qcf.js` بتحميل خط الصفحة عند اقتراب آياتها من مجال
الرؤية، فلا تُجلب كل خطوط الصفحات المتوفرة (نحو 25 ميغابايت) دفعة واحدة.

> إذا أضفت سورة جديدة، شغّل `python tools\build_qcf_data.py` ثم أعد تشغيل
> `python tools\build_quran_data.py` إن استخدمت `--no-index`. وإذا غاب خط صفحة أو فشل
> تحميله، يبقى النص العادي ظاهرًا بدل ظهور مربعات.

### مسار بيانات مخصّص

لأي استضافة مختلفة، أضف قبل تحميل `js/app.js` في `index.html`:

```html
<script>window.QURAN_DATA_BASE = "https://example.com/quran-data/";</script>
```

## الميزات

- قائمة السور الـ114 مع تصفية فورية بالاسم أو الرقم، وشارات توفّر النص/الصوت،
  ومرشّح «المتوفرة» لإخفاء السور غير الجاهزة.
- قراءة الآيات بخط quran.com نفسه: نصوص QCF وخط مستقل لكل صفحة مصحف، مع الخط العثماني
  الموحّد كخط أساسي واحتياطي وأرقام الآيات.
- تشغيل التلاوة ومزامنة تظليل الآية الحالية مع الصوت (`start_ms`).
- تحكم كامل: تشغيل/إيقاف، السابق/التالي، شريط تقدم، سرعة التشغيل، تكرار الآية.
- تمرير تلقائي مع التلاوة (يمكن إيقافه).
- الانتقال المباشر لأي آية بالنقر عليها.
- تصفّح الأجزاء (30) والأحزاب (60) والأرباع (240).
- بحث نصي في كل السور المتوفرة، متسامح مع التشكيل وصور الهمزة، ويعتمد على فهرس مسبق
  (تحميل واحد) بدل تجربة 114 ملفًا في كل مرة.
- تفسير الآية عند توفّر ملف `quran-data/tafsir`.
- علامات مرجعية، وآخر موضع للاستئناف.
- «مشواري مع القرآن»: نسبة الإنجاز، الجزء الحالي، المعدل اليومي، المستوى، والتنبيه عند إتمام جزء.
- إعدادات: حجم الخط، الثيم (كلاسيكي/فاتح/داكن)، النمط (المصحف المزخرف/معاصر)، التمرير التلقائي.
- واجهة متجاوبة تعمل على الجوال، مع قائمة جانبية منسدلة.

## البنية

```
web/
  index.html              الواجهة
  css/app.css             التنسيقات والثيمات
  css/qcf-fonts.css       (مُولَّد) قواعد @font-face لخطوط QCF لكل صفحة
  assets/fonts/           خط UthmanicHafs1Ver18.woff2 (نسخة quran.com)
  assets/fonts/qcf/       (مُولَّد) خطوط صفحات QCF pNNN.woff2
  js/app.js               ربط الواجهة والأحداث
  js/reader.js            عرض الآيات ومزامنة الصوت
  js/qcf.js               تحميل خطوط QCF تدريجيًا والتحقق منها
  js/data.js              تحميل البيانات والبحث
  js/divisions.js         الأجزاء والأحزاب والأرباع
  js/progress.js          منطق «مشواري»
  js/storage.js           التخزين المحلي
  serve.py                خادم محلي يدعم Range
  serve.ps1               تشغيل سريع للخادم
  tests/smoke.spec.js     اختبارات Playwright
  playwright.config.js    إعداد الاختبارات (يشغّل الخادم تلقائيًا)
  package.json            تبعيات الاختبارات فقط (التطبيق بلا أدوات بناء)
```

## الاختبارات

اختبارات الدخان تتحقق من ظهور النص (ومنع رجوع خلل تغطية الآيات)، وتحميل الخط الأساسي
وتطبيق خط QCF على الآيات مع التحميل التدريجي، وفتح التفسير والقفز بالصوت، ورسالة السورة
الناقصة دون طلب 404، والبحث بالفهرس المسبق، وحفظ الإعدادات.

```powershell
cd web
npm install          # أول مرة فقط
npm test             # أو: npm run test:headed
```

- محليًا يستخدم Playwright متصفح **Edge** المثبّت، وفي CI يستخدم Chromium.
- الاختبار الذي يقفز بالصوت يُتجاوز تلقائيًا إذا لم تكن ملفات `quran-data/audio` موجودة
  (لأن الصوت يُوزَّع خارج Git).
- يشغّل Playwright خادم `web/serve.py` تلقائيًا على المنفذ 8130 أثناء الاختبار.
- نفس الاختبارات تعمل في GitHub Actions عبر `.github/workflows/ci.yml`.

## التخزين المحلي

| المفتاح | المحتوى |
| --- | --- |
| `qss.settings.v1` | الإعدادات |
| `qss.bookmarks.v1` | العلامات المرجعية |
| `qss.lastPosition.v1` | آخر موضع |
| `qss.progress.v1` | تقدّم المشوار |
| `qss.trackingPaused.v1` | حالة إيقاف/استئناف المتابعة |

كل شيء محلي؛ لا يُرسل أي شيء إلى خادم. لمسح البيانات: أدوات المتصفح ← بيانات الموقع ← حذف.

## ملاحظات

- لا توجد حسابات/كلمات مرور في نسخة الويب؛ كل متصفح = ملف مستخدم مستقل.
- اختصارات: `مسافة` تشغيل/إيقاف، `←` الآية التالية، `→` الآية السابقة (عند عدم الكتابة في حقل).
